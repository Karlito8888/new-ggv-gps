## 📋 Synthèse du projet

PWA de navigation GPS pour Garden Grove Village (Philippines) — React 19 + MapLibre GL 5 + Vite 7 + Supabase. Architecture mono-composant `App.tsx` avec hooks customisés, routing OSRM/ORS/direct, service worker offline, et 6 états de navigation.

### Stack technique

| Techno         | Version | Rôle                |
| -------------- | ------- | ------------------- |
| React          | 19.2.5  | UI framework        |
| MapLibre GL JS | 5.23.0  | Carte vectorielle   |
| Vite           | 7.3.2   | Build tool          |
| TypeScript     | 5.9.3   | Typage statique     |
| Framer Motion  | 12.38.0 | Animations overlays |
| Supabase JS    | 2.104.0 | Backend block/lot   |
| PMTiles        | 4.4.1   | Tuiles vectorielles |
| Workbox        | 7.4.0   | Service worker PWA  |
| React Compiler | 1.0.0   | Optimisation auto   |

### 2.1 `.env` potentiellement dans le dépôt Git

Le fichier `.env` (431 bytes) est **présent physiquement** mais listé dans `.gitignore`.

- ~~Si tracké : `git rm --cached .env` puis nettoyer l'historique~~ — Pas nécessaire

### 2.2 CSP autorise `'unsafe-inline'`

```html
<!-- index.html -->
script-src 'self' 'unsafe-inline' blob: style-src 'self' 'unsafe-inline'
```

`'unsafe-inline'` annule une grande partie de la protection CSP.

- [x] Utiliser un hash ou nonce pour les styles/scripts inline — ✅ Fait (22/04) : `unsafe-inline` retiré, pas nécessaire en prod
- [x] Ou migrer les styles inline vers des classes CSS — ✅ Déjà en classes CSS

### 2.3 Clé API ORS exposée côté client

La clé `VITE_OPENROUTE_API_KEY` est embed dans le bundle JS client. Acceptable pour du routing public, mais :

- [ ] Ajouter des restrictions de domaine (referrer) sur le dashboard ORS
- [ ] Envisager un proxy API pour masquer la clé

### 2.4 Incohérence nommage variable `.env.example`

`.env.example` documente `VITE_SUPABASE_ANON_KEY` mais le code (`supabase.ts`) utilise `VITE_SUPABASE_PUBLISHABLE_DEFAULT_KEY`.

- [x] Corriger `.env.example` pour refléter le vrai nom de variable — ✅ Fait (22/04)

Acceptable car toutes les ressources sont self-hosted. ✅

### 5.1 ✅ Bonnes pratiques déjà en place

- Pas de `// eslint-disable-next-line` sauf un seul (justifié pour le mount effect)

### 5.2 ⚠️ Améliorations possibles

#### a) `fetchBlocks` dans `App.tsx` n'est pas stable

```tsx
const fetchBlocks = () => { ... };
useEffect(() => { fetchBlocks(); }, []);
```

La fonction `fetchBlocks` est recréée à chaque render.

- [x] Envelopper dans `useRef` ou extraire hors composant — ✅ Fait (22/04) : logique inlinée dans le useEffect (pattern React docs)

#### b) Multiple `useEffect` avec dépendances complexes

L'effet d'orientation a un `// Note: no navState dependency - uses ref instead` — pattern légitime mais fragile.

- [x] Documenter le pattern ou utiliser `useEffectEvent` (React 19) — ✅ Déjà implémenté dans `useDeviceOrientation.ts` avec commentaires appropriés

#### c) Pas de Error Boundary

Si MapLibre ou Supabase lance une erreur, l'app crash sans récupération.

- [x] Ajouter un `<ErrorBoundary>` autour de `App` — ✅ Fait (22/04)

### 5.3 Violation du rendu conditionnel

```tsx
{navState === "navigating" && !showArrivedModal ? (
  <NavigationOverlay ... />
) : null}
```

- [x] Utiliser un ternaire `condition ? <Component /> : null` au lieu de `&&` pour éviter le rendu accidentel de `0` ou `""` — ✅ Fait (22/04)
